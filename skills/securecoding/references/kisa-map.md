# KISA 소프트웨어 개발보안 가이드와 통제 대응표

출처: 행정안전부·한국인터넷진흥원의 『전자정부 SW 개발·운영자를 위한 소프트웨어 개발보안 가이드』 2021.12.29 판 (PDF 381쪽). 가이드는 가공 및 인용 시 이 출처 표기를 요구한다. 원문 전재는 하지 않았다. 설계단계 보안설계 기준 20개 (제3장) 및 구현단계 보안약점 49개 (제4장) 를 읽고 통제 ID 에 대응시켰다. 쪽은 인쇄 쪽 기준. 2023년 개정(v4.0) 판은 이 문서에서 확인하지 못했다.
표기: `대응` 통제가 그 항목을 직접 다룸, `일부` 통제가 한 면만 다룸, `언어` 해당 언어를 쓸 때만 적용 (웹 서비스에서 JavaScript, Python 만 쓰면 `NOT_APPLICABLE`).

## 3. KISA 가이드와 다른 기준의 차이 (적용 때 확인)
- **비밀번호 저장 (2-14)**: 가이드 예제는 솔트를 붙인 SHA-256 이다. SEC-03 은 OWASP 원문에 따라 비밀번호 전용 해시 (Argon2id 우선) 를 쓰고 단순 SHA-256 을 금지한다. 국내 점검에서 `솔트 사용` 여부를 묻는 항목은 비밀번호 전용 해시가 솔트를 포함하므로 충족하는지 점검자에게 확인한다
- **비밀번호 조합 규칙 (2-9)**: 가이드는 숫자, 영문자, 특수문자 혼합과 자릿수 검증 및 주기적 변경 유도를 제시한다. 다른 기준 (OWASP Authentication Cheat Sheet) 과 요구가 다를 수 있다. 적용 전 해당 원문을 먼저 읽는다 (이 문서에서 대조하지 않음)
- **인증 시도 횟수 (2-16)**: 가이드에 구체 횟수가 없다. SEC-02 의 5회는 사용자 정책이다
- **암호 알고리즘 (2-4)**: 가이드는 국내 검증 암호모듈과 ARIA, SEED 를 함께 제시한다. 공공 및 개인정보 시스템에서 국산 암호 요구가 있는지는 해당 고시와 발주 요건으로 확인한다

## 4. 가이드의 한계 (읽은 범위)
- 요약은 보안대책 문장 중심이며 코드 예제의 정확성은 검증하지 않았다. 일부 안전 코드 예제에 로직 오류가 있다 (5-1, 7-1)
- 5-5 의 보안대책 문단에 5-4 문단이 겹쳐 들어 있다
- 가이드 부록의 산출물 예시 ID 가 일부 중복 인쇄되어 있다 (파일 업로드, 관리자 페이지)
