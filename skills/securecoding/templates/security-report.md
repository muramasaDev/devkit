# 보안 점검 보고

- 프로젝트:
- 점검 일자:
- 시험일:
- 담당자:
- 점검 대상 커밋 해시:
- 시험 환경 (URL, 개발 또는 시험 환경만):
- 도구 및 버전 (자동 점검과 시험에 쓴 것 전부):
- 범위 (코드 검토 / 자동 점검 / 악용 시나리오 시험 중 실행한 것):
- 프로젝트 성격 (개인정보, 인증 방식, 인터넷 또는 폐쇄망, 외부 연동):

상태 값
- `PASS(시험)`: 요청을 실제로 보내 통과 기준을 확인함
- `PASS(검사: 파일:줄 및 명령 출력)`: 검사 자체가 증거인 통제 (예: SEC-03 해시 설정값, SEC-16 lockfile). 확인한 파일과 줄, 명령 출력을 근거 칸에 적는다
- `FAIL`: 결함 확인. 심각도, 재시험 날짜, 재시험 결과 칸을 채운다
- `NOT_APPLICABLE`: 해당 없음 (이유 필수)
- `NOT_TESTED`: 실행하지 않음

실행하지 않은 시험은 PASS 로 적지 않는다. 코드를 읽고 맞다고 판단한 것은 시험이 아니다.
