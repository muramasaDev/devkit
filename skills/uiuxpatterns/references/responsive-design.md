# Responsive Design Guidelines

- 역할: 모바일, 태블릿, 데스크톱에서 화면 구성 및 패턴을 정하는 기준
- 원칙: 화면을 줄이는 것이 아니라 콘텐츠 우선순위와 인터랙션 방식을 함께 다시 정한다. 필요하면 화면 크기에 따라 서로 다른 패턴을 고른다

## 1. 먼저 확인
- 기존 중단점: CSS 미디어 쿼리, 컨테이너 쿼리, 프레임워크 설정에 있는 값을 그대로 쓴다. 새 값을 만들지 않는다
- 중단점이 없는 프로젝트: 내용이 깨지는 지점에서 정한다. 기기 이름에 맞춘 값을 지어내지 않는다
- 입력 방식: 화면 너비가 아니라 `pointer` 및 `hover` 미디어 특성으로 터치 여부를 구분한다 (너비가 넓은 터치 기기, 좁은 창의 데스크톱이 있음)
- 뷰포트 설정: `<meta name="viewport" content="width=device-width, initial-scale=1">`. 확대를 막지 않는다 (`user-scalable=no` 금지)

## 2. 기기 특성

| 구분 | 특성 | 설계에 반영 |
|---|---|---|
| 모바일 | 좁은 한 열, 터치, 한 손 조작, 화면 키보드가 화면을 가림, hover 없음 | 주 행동을 손이 닿는 아래쪽에, 한 화면에 한 가지 일, 입력 종류에 맞는 `type` 및 `inputmode` 및 `autocomplete`, 고정 요소가 화면 키보드에 가려지지 않게 |
| 태블릿 | 중간 너비, 터치 및 키보드 병행, 가로 및 세로 전환 | 2열 또는 목록 및 상세 나란히, 방향 전환 시 상태 유지 |
| 데스크톱 | 넓은 화면, 마우스 및 키보드, hover, 여러 창 | 높은 정보 밀도 가능, 키보드 단축 수단, 줄 길이 제한, 넓은 화면에서 내용이 과하게 늘어나지 않게 최대 너비 |

## 3. 화면 크기에 따라 바뀌는 패턴

| 상황 | 모바일 | 데스크톱 |
|---|---|---|
| 최상위 이동 | NV-01 Tab bar 또는 NV-03 Drawer | 사이드바 또는 상단 내비게이션 |
| 항목의 보조 행동 | FB-05 Bottom sheet, GS-02 Long press | 드롭다운 메뉴, 우클릭 메뉴, 행에 보이는 단추 |
| 확인 및 짧은 입력 | FB-05 Bottom sheet 또는 전체 화면 | FB-04 Modal dialog |
| 보충 설명 | 탭해서 여는 설명 (hover 없음) | FB-07 Tooltip |
| 목록 항목 삭제 | GS-04 Swipe to delete 및 보이는 대체 수단 | 행의 삭제 단추 또는 메뉴 |
| 순서 바꾸기 | GS-05 Drag 및 위아래 이동 단추 | 드래그 및 키보드 이동 |
| 새로고침 | GS-08 Pull to refresh | 새로고침 단추 또는 자동 갱신 |
| 뒤로 가기 | NV-09, GS-09 (OS 제스처) | 브라우저 뒤로 가기, 화면 안 뒤로 가기 단추 (상위 계층 이동은 NV-04 Breadcrumb) |
| 표 | 카드 목록 또는 핵심 열만 및 상세 화면 | 표 |
| 날짜 입력 | 기본 날짜 입력 (`<input type="date">`) | 달력 및 직접 입력 |
| 필터 | 시트 또는 전체 화면에서 설정 후 적용 | 옆 패널에서 즉시 적용 |
| 주 행동 | NV-06 Floating action button 또는 아래 고정 단추 | 헤더 또는 내용 옆 단추 |

- 위 표는 후보이고, 기존 프로젝트가 이미 쓰는 방식이 있으면 그것을 따른다
- 패턴을 바꾸더라도 기능은 같아야 한다. 모바일에서 기능을 빼지 않는다

## 4. 콘텐츠 우선순위
1. 화면마다 사용자의 목적 하나와 주 행동 하나를 정한다
2. 좁은 화면에서는 그 목적에 필요한 내용을 먼저 놓고, 나머지는 아래로 내리거나 접는다 (숨겨서 없애지 않는다)
3. 넓은 화면에서 생긴 자리는 같이 봐야 하는 정보(목록 및 상세, 요약 및 본문)에 쓴다. 빈자리를 채우려고 내용을 늘리지 않는다
4. DOM 순서와 보이는 순서를 같게 유지한다 (초점 순서, WCAG 2.4.3)

## 5. 배치 기법
- 내용 기반 유동 배치를 먼저 쓴다: Flexbox, Grid (`auto-fit`, `minmax()`), `clamp()`, 컨테이너 쿼리 (프로젝트가 지원하는 범위에서)
- 고정 너비 및 고정 높이를 피한다. 글자가 늘어도 잘리지 않게 한다 (번역, 글자 확대)
- 이미지는 고유 비율을 지정해 로딩 중 배치가 밀리지 않게 한다
- 가로 스크롤은 표, 코드, 캐러셀 등 의도한 영역 안에서만 둔다
- 아래 고정 요소는 안전 영역(`env(safe-area-inset-*)`)을 반영한다 (뷰포트 설정에 `viewport-fit=cover` 가 있어야 값이 들어옴)

## 6. 점검
| 항목 | 방법 |
|---|---|
| 320 CSS px 너비에서 가로 스크롤 없이 사용 (WCAG 1.4.10) | 창을 좁혀 확인 |
| 글자 200% 확대에서 내용 및 기능 유지 (WCAG 1.4.4) | 브라우저 확대 |
| 가로 및 세로 방향 모두 사용 가능 (WCAG 1.3.4) | 기기 또는 개발자 도구 |
| 터치 목표 크기 (`accessibility.md`) | 요소 크기 측정 |
| hover 에만 있는 기능 없음 | 터치 모드로 확인 |
| 화면 키보드가 입력 칸 및 제출 단추를 가리지 않음 | 실제 기기 또는 에뮬레이터 |
| 중단점 경계 값 바로 앞뒤에서 깨지지 않음 | 창 너비를 경계 값 근처로 조절 |
| 긴 글, 긴 이름, 자료 0건 및 다수 건에서 배치 유지 | 시험 자료로 확인 |

- 실제 기기로 확인하지 못하고 개발자 도구로만 본 경우 보고에 그렇게 적는다
