
# UI/UX 용어집과 현장 점검 질문

## 쓰는 법
- 화면을 시킬 때와 고칠 때 모호한 말 (`로딩 넣어 줘`, `부드럽게`) 대신 아래 이름으로 말한다. `로딩 넣어 줘` 는 스피너만 들어간다.
- 화면을 검수할 때는 맨 아래 점검 질문을 현재 화면에 대 본다. 현재 화면은 캡처로 눈으로 확인하고, 코드만 본 것은 `코드 확인` 으로 구분해 적는다.
- 같은 주제를 더 자세히 다루는 파일은 맨 아래에 있다.

## 1. 빈 화면 9종 (원칙: 이유 한 줄 + 다음에 누를 것 하나)
| 이름 | 쓰는 때 | 되돌림 단추 |
|---|---|---|
| 첫 사용 (First use) | 처음 들어와 자료가 없음 | 시작 행동 (예: 구경하러 가기) |
| 검색 결과 없음 | 검색어에 맞는 것이 없음 | 다른 검색어 안내, 검색어 지우기 |
| 필터 결과 없음 | 필터 조건에 맞는 것이 없음 | 필터 초기화 |
| 오프라인 | 연결이 끊김 | 다시 시도 |
| 권한 필요 | 알림 등 허용이 필요 | 허용 토글 |
| 모두 완료 (All caught up) | 할 일을 다 끝냄 | 초록 체크 등 긍정 표시로 끝냄 |
| 삭제 직후 (Emptied) | 방금 비움 | 담으러 가기 |
| 오류 (Error state) | 불러오지 못함 | 다시 불러오기 |
| 잠김 (Locked) | 권한 없어 못 봄 | 안내 단추 |
- 한 문구 (`데이터가 없습니다`) 로 뭉개지 않는다. 이유는 첫 줄에 한 줄로 쓴다 (사실만).
- 되돌릴 방법이 사용자에게 없는 경우 (서버에 자료 없음) 는 단추를 지어내지 않고 이유만 쓴다.

## 2. 메뉴 아이콘 별명 9종
햄버거 (줄 3개), 케밥 (세로 점 3개), 미트볼 (가로 점 3개), 와플 (점 9개), 벤토 (네모 9개), 도너 (위가 넓은 줄 3개, 필터 모양), 베지 버거 (줄 2개), 계단 (계단식 줄 3개), 슬라이더 (조절 줄 3개).
- 실무에서 널리 쓰는 것은 햄버거와 케밥 정도. 나머지는 해외 커뮤니티 별명이므로 팀에서 부르는 이름을 정해 둔다.
- 글자 없는 아이콘 단추는 마우스를 올리면 보이는 설명 (title) 과 접근성 이름 (aria-label) 을 둔다.

## 3. 화면 이동 9종
하단 탭바, 상단 탭 (밑줄 이동), 드로어 (옆에서 밀려 나오는 메뉴), 브레드크럼 (홈 > 가전 > 무선 이어폰), 고정 헤더 (스크롤해도 위에 붙음), 플로팅 버튼 (주 행동, 늘어나는 알약), 페이지네이션, 무한 스크롤, 뒤로 가기 (`<` 왼쪽 위).
- 현재 위치는 한 곳만 강조한다 (현재 탭 하나만 채움 또는 밑줄).
- 무한 스크롤과 페이지네이션은 목록 성격으로 고른다.

## 4. 움직임 이름 9종
- 속도 곡선: 이즈 인 (천천히 출발), 이즈 아웃 (끝에서 천천히 멈춤), 스프링 (넘쳤다 복귀), 바운스 (바닥에서 튕김)
- 등장 방식: 순차 등장 (한 줄씩 시차), 페이드, 슬라이드
- 화면 전환: 확대 전환, 공유 요소 전환 (목록 이미지가 상세 이미지로 이어짐)
- `부드럽게` 가 아니라 `끝에서 천천히 멈추게 (이즈 아웃)` 처럼 지시한다. 시간 값은 제품에서 직접 정한다. 움직임 줄이기 (prefers-reduced-motion) 설정에서는 끈다.

## 5. 로딩 패턴 9종 (쓰는 때)
| 이름 | 쓰는 때 |
|---|---|
| 스피너 | 2초 안에 끝나는 짧은 대기 |
| 스켈레톤 | 피드와 카드처럼 모양이 정해진 화면 |
| 진행 바 | 업로드처럼 끝이 보이는 작업 (이름과 퍼센트) |
| 진행 링 | 좁은 자리에 퍼센트 |
| 단계 표시 | 가입과 결제처럼 여러 단계 |
| 블러 업 | 큰 이미지가 늦게 뜰 때 |
| 낙관적 UI | 좋아요와 저장처럼 실패가 드문 동작 (서버 응답 전에 먼저 반영, 알림으로 확인). 실패가 잦거나 결과가 중요한 동작에는 쓰지 않는다 |
| 스트리밍 텍스트 | AI 답변처럼 길게 생성되는 글 |
| 로딩 버튼 | 누른 단추 안에서 처리 중 표시, 끝나면 완료 표시 |

## 점검 질문 (화면 검수용)
1. 비어 있는 곳마다 이름 (9종 중 무엇) 과 이유 한 줄과 되돌림 단추가 있는가
2. 기다리는 곳마다 맞는 로딩 패턴이 있는가 (짧으면 아무것도 바꾸지 않고, 길면 스켈레톤)
3. 현재 위치가 한 곳만 강조되고 경로가 보이는가, 긴 화면에 현재 구간 표시가 있는가
4. 글자 없는 아이콘에 설명과 접근성 이름이 있는가
5. 움직임이 이름 붙은 몇 가지로 한정되고, 시간 값이 한 곳에서 정해지고, 줄이기 설정을 따르는가
6. 누른 단추가 그 자리에서 처리 중임을 보여 주고 끝나면 완료로 이어지는가
7. 화면 요소를 부르는 이름이 설계 문서, 코드, AI 지시에서 같은가
