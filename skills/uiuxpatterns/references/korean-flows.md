# Korean Flows (국내 서비스 핵심 흐름)

- 역할: 국내 서비스에서 반복되는 흐름 6개의 화면 상태, 오류 문구 예, 접근성 요구
- 근거 표기: `확인` 원문을 읽음 (MDN, W3C WCAG 2.2, 로컬 실행. 2026-11-25), `일반` 읽은 원문 없는 일반 권고, `미확인` 확인하지 못함
- 오류 문구 예는 서비스 문체에 맞춰 바꿔도 된다. 괄호 안 `{ }` 는 서버가 준 값으로 채운다
- 패턴 ID 는 `pattern-catalog.md`, 시간 값은 `defaults.md`

## 1. 휴대폰 본인확인
- 입력 칸: 번호 `type="tel"`, `autocomplete="tel"` (확인: MDN 의 `tel` 은 국가 코드를 포함한 전체 번호). 인증번호 `autocomplete="one-time-code"` (확인: SMS, 이메일, 인증 앱으로 받는 일회용 코드), `inputmode="numeric"` (확인: 숫자 0~9 키보드만 띄우고 입력 검증은 하지 않음)
- 통신사 선택은 본인확인 제공사가 주는 목록을 쓴다 (일반). 같은 과정에서 이미 입력한 번호가 다시 필요하면 자동으로 채우거나 고를 수 있게 한다 (확인: WCAG 3.3.7, 보안 목적 재입력은 예외)
- 남은 시간은 서버가 준 만료 시각으로 계산한다 (`dark-patterns.md` DP-03 대체 UX). 시간 제한이 있으면 만료 전 경고와 연장 수단을 둔다 (확인: WCAG 2.2.1, 20초 이상 경고 및 간단한 동작으로 연장, 10회 이상). 매초 낭독하지 않고 시작, 1분 단위, 만료 직전에만 알린다 (일반)
- 재전송은 횟수 및 대기 시간을 서버 정책 값으로 표시하고 화면에 숫자를 지어내지 않는다 (일반)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 번호 입력, 발송 중, 발송됨, 확인 중, 완료 | 번호 형식이 맞지 않아요. 숫자만 입력해 주세요 | 칸 `<label>`, 오류는 `aria-describedby` 로 연결 (3.3.1) |
| 일치하지 않음 | 인증번호가 일치하지 않아요. 다시 확인해 주세요 | 입력값 유지, 오류 칸에 초점 |
| 시간 만료 | 인증 시간이 지났어요. 인증번호를 다시 받아 주세요 | 만료를 `role="status"` 로 1회 알림 (4.1.3) |
| 재전송 제한 | 요청 횟수를 넘었어요. {n}분 뒤에 다시 시도해 주세요 | 비활성 단추에 이유 한 줄 (`interaction-rules.md` 1절) |

## 2. 결제
- 결제창(PG)이 새 창이나 팝업이면 사용자 클릭 처리 안에서 연다. 클릭 뒤 비동기 작업을 거쳐 열면 브라우저가 차단할 수 있다 (일반, 브라우저별 정책은 미확인). 차단되었을 때의 안내를 둔다
- 중복 결제 방지: 클릭 즉시 단추를 처리 중으로 바꾸고 (`loading.md` LD-06), 서버도 같은 주문의 재요청을 거른다 (일반)
- 결제 중 뒤로 가기 및 새로고침: 결과를 화면 상태가 아닌 서버의 주문 상태로 확인해 보여 주고, 새로고침이 재결제가 되지 않게 한다 (일반)
- 결제 직전 요약에 총액 및 수수료를 처음부터 보인다 (DP-07)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 결제 전, 결제창 열림, 결과 확인 중 | 결제창이 열리지 않았어요. 팝업 차단을 풀고 다시 눌러 주세요 | 처리 중 단추 `aria-disabled`, 상태 변화 `role="status"` |
| 확인 중 | 결제 결과를 확인하고 있어요. 이 화면을 닫지 말아 주세요 | 닫아도 되는지 여부를 글로 알림 |
| 성공 | (오류 없음) 주문번호 및 금액 표시 | 결과 제목으로 초점 이동 (일반) |
| 실패, 취소 | 결제가 완료되지 않았어요. 결제 수단을 확인하고 다시 시도해 주세요 | 실패와 취소를 구분해 표시, 색만으로 구분 금지 (1.4.1) |

## 3. 금액 표기
- `new Intl.NumberFormat('ko-KR', { style: 'currency', currency: 'KRW' }).format(19000)` 은 `₩19,000` (확인: Node v24.22.1 에서 실행). `currencyDisplay: 'name'` 은 `19,000 대한민국 원`. `원` 으로 쓰려면 숫자에 `toLocaleString('ko-KR')` 를 쓰고 `원` 을 붙인다
- `19000.6` 은 `₩19,001` 로 반올림된다 (확인: 같은 실행). 금액은 서버가 준 정수 원 값을 그대로 보이고 화면에서 계산해 반올림하지 않는다 (일반)
- 입력 칸은 `inputmode="numeric"`, 쉼표는 표시에만 쓰고 전송 값은 숫자만 (일반). 열 정렬은 `tabular-nums` (`design-system.md`)
- 스크린 리더가 `₩` 를 어떻게 읽는지는 미확인이다. 낭독이 중요한 곳은 `원` 글자로 쓴다 (일반)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 값 없음, 0원, 큰 값 | 금액을 숫자로 입력해 주세요 | 금액 변경은 `role="status"` 로 알림 (DP-05) |

## 4. 주소 입력
- 칸 분리: 우편번호, 도로명 또는 지번 주소(검색으로 채움), 상세 주소. `autocomplete` 는 `postal-code`, `address-line1`, `address-line2` (확인: MDN 값 설명). `street-address` 는 한 칸에 전체를 받을 때만 쓴다
- 주소 검색 서비스(위젯 또는 API)를 쓰면 위젯 접근성은 제공사별로 확인한다 (미확인). 선택이 끝나면 상세 주소 칸으로 초점을 옮긴다 (일반)
- 우편번호 자릿수 및 도로명 및 지번 표기는 주소 제공 서비스의 응답 값을 따른다 (자릿수 규정은 미확인)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 비어 있음, 검색 중, 결과 없음, 선택됨 | 주소를 검색해 선택해 주세요 | 검색 결과 수를 `role="status"` 로 알림 |
| 상세 주소 누락 | 상세 주소를 입력해 주세요 | 오류 칸에 초점, 값 유지 |

## 5. 한글 입력
- 조합 중 Enter 및 Escape, 검색 디바운스, 글자 수 계산의 정본은 `interaction-rules.md` 2절, `modern-web.md` 입력 표, `defaults.md` DF-27 이다. 여기서 다시 정하지 않는다
- 이 흐름의 점검: 한글로 입력하는 모든 제출 칸에서 마지막 글자가 조합 중일 때 Enter 를 눌러 제출이 한 번만 되는지 실제 입력기로 확인한다 (일반)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 조합 중, 확정 | 글자 수를 넘었어요. {max}자까지 입력할 수 있어요 | 글자 수는 조합 확정 뒤 갱신, 낭독 폭주 방지 |

## 6. 개인정보 동의 화면
- 필수 및 선택을 구역으로 나누고 선택 항목은 기본 해제한다. `전체 동의` 는 사용자가 누를 때만 하위 항목을 켠다 (`dark-patterns.md` DP-02). 선택 항목에 동의하지 않아도 서비스를 쓸 수 있어야 한다. 조문은 같은 파일의 `법규 대응 (대한민국)` 절
- 약관 전문은 링크로 열고 새 창이면 그 사실을 링크 글자에 적는다 (일반)

| 화면 상태 | 오류 문구 예 | 접근성 요구 |
|---|---|---|
| 모두 해제, 일부 선택, 전체 선택 | 필수 항목에 동의해야 가입할 수 있어요 | `<fieldset>` 및 `<legend>`, 항목마다 `<label>` (3.3.2). `전체 동의` 가 네이티브 체크박스면 일부 선택일 때 스크립트로 `indeterminate = true`. 직접 만든 체크박스만 `aria-checked="mixed"` (확인: ARIA in HTML 은 `input type=checkbox` 에 `aria-checked` 사용을 금지) |

## 이 파일이 다루지 않는 것
- 본인확인 및 PG 연동 규격, 제공사별 화면과 오류 코드
- 간편인증, 공동인증서, 금융 보안 프로그램 설치 흐름
- 주민등록번호 수집 및 보관, 만 14세 미만 법정대리인 동의
- 법정 필수 고지 문구의 내용, 결제 수단별 입력 화면, 해외 통화, 앱 스토어 결제
- 주소 검색 위젯 내부 구현, 우편번호 규정
- 국내 보조기기(센스리더 등) 버전별 낭독 차이
