# Interaction Rules (상호작용 세부 규칙)

- 역할: 패턴 90개를 구현할 때 놓치기 쉬운 동작 규칙. 접근성과 한글 입력 환경에서 자주 틀리는 것 위주
- 근거: 공개된 대형 디자인 시스템의 접근성 및 컴포넌트 명세와 웹 플랫폼 지침을 2026-11-25 에 요약본으로 읽었다. 원문과 한 글자까지 같지 않으므로 문구를 인용하거나 규정에 쓰기 전에 원문을 다시 확인한다
- 표기: `확인` 규칙 본문을 읽음, `요지` 요약본에서만 확인

## 1. 비활성 컨트롤
- 네이티브 `disabled` 대신 `aria-disabled` 를 쓰면 포커스가 유지되고 비활성인 이유를 보조기기에 알릴 수 있다 (확인)
- 포커스 링은 비활성이어도 유지한다 (확인)
- 비활성 이유를 화면에도 한 줄로 적는다 (일반 UX 권고)

## 2. 입력과 검증 시점
- 입력이 끝나기 전에는 오류를 보이지 않는다. 입력을 확정하는 시점 (칸을 떠날 때, 제출할 때) 에 보인다 (확인)
- 오류는 보이는 메시지, `aria-invalid`, 한 번의 안내를 함께 쓴다. 거절한 입력은 지우지 않고 남겨서 고칠 수 있게 한다 (확인)
- 값이 바뀌어도 입력 칸의 너비가 변하지 않게 한다. 끝 컨트롤 (지우기, 스피너) 이 글자와 겹치지 않게 한다 (요지)
- 모바일 사파리에서 포커스될 때 확대되지 않도록 입력 글자는 16px 이상으로 한다 (요지)
- 포커스된 칸이 모바일 키보드에 가려지지 않게 한다. 검색 입력에는 `enterkeyhint="search"` (요지)
- 한글, 일본어, 중국어 조합 중 Enter 와 Escape 는 제출이나 닫기로 동작하지 않게 한다. `isComposing` 과 `keyCode 229` 를 검사한다 (확인)

## 3. 상태 안내 (스크린 리더)
- 같은 메시지를 안내하는 주체는 하나만 둔다. 같은 사건은 한 번만 안내한다 (확인)
- `polite` 와 `assertive` 라이브 영역을 문서당 하나씩 처음부터 마운트해 두고 메시지만 바꾼다 (확인)
- 페이지를 열 때 이미 있던 메시지는 안내하지 않는다. 스피너는 소리를 내지 않는다 (확인)
- 상태를 색만으로 나타내지 않고 아이콘이나 글자를 함께 쓴다. 로딩 중에도 레이아웃이 밀리지 않는다 (확인)

## 4. 오버레이 닫기
- Escape 한 번은 가장 위의 레이어 하나만 닫는다 (확인)
- 배경을 눌러 닫을 때는 누르기 시작과 끝이 모두 배경일 때만 닫는다. 안에서 드래그하다 배경에서 끝나도 닫히지 않게 한다 (확인)
- 닫으면 열었던 요소로 포커스를 돌려보내고, 이때 스크롤이 움직이지 않게 한다 (확인)

## 5. 토스트
- 정보성은 5초 뒤 자동으로 닫고 오류는 자동으로 닫지 않는다 (확인)
- 마우스를 올렸을 때, 포커스가 있을 때, 터치하는 중, 창이 비활성일 때는 타이머를 멈춘다 (확인)
- 닫힐 때 포커스가 `body` 로 떨어지지 않게 한다. 키보드로 최신 토스트로 이동하는 단축키 (F6) 를 제공한다 (확인)

## 6. 채팅과 긴 스트림
- 스트리밍 중에는 맨 아래를 따라간다. 사용자가 위로 스크롤하면 따라가기를 멈추고 `맨 아래로` 단추를 보인다 (확인)
- 숨겨진 단추는 포커스를 받지 않는다. 새 메시지가 오면 단추 이름에 그 사실을 반영한다 (확인)

## 7. 움직임과 호버
- reduced-motion 에서는 이동, 확대, 스프링을 쓰지 않는다. 터치 환경은 투명도 변화만, 200ms 이하로 한다. 설정으로 완화할 수 있게 하지 않는다 (확인)
- 호버 스타일은 `@media (hover: hover)` 안에서만 적용한다. (확인)

## 8. 응답 시간 기준
- 입력 후 화면이 바뀌는 시간은 INP 200ms 이하를 목표로 한다. 눌림 상태를 즉시 그리고 무거운 일은 뒤로 미룬다 (`terms-extended.md` 성능 체감)
- 응답이 0.4초 안에 끝나지 않으면 중간 결과를 보이거나 낙관적으로 먼저 반영한다 (`terms-extended.md` Doherty Threshold)
