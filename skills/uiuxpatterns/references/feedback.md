# Feedback & Notifications (알림과 피드백)

- 범위: 사용자 행동의 결과, 상태 변화, 주의가 필요한 내용을 알리는 메시지 및 안내 패턴 9종
- 색인: `pattern-catalog.md`
- 값 정본: `defaults.md` (본문의 DF-nn 은 그 표의 항목 번호)

## 유사 패턴 구분

| 헷갈리는 쌍 | 고르는 기준 |
|---|---|
| 토스트(FB-01) 대 스낵바(FB-02) | 사용자가 눌러야 할 행동 단추가 있으면 스낵바(되돌리기 등), 알리기만 하고 행동이 없으면 토스트 |
| 배너(FB-03) 대 토스트(FB-01) | 화면에 머무는 동안 계속 보여야 하고 사용자가 닫기 전까지 남아야 하면 배너, 잠깐 보였다 스스로 사라져도 되면 토스트 |
| 모달(FB-04) 대 바텀시트(FB-05) | 진행 전에 반드시 결정을 받아야 하고 나머지 화면을 막아야 하면 모달, 관련 동작 목록 중 하나를 고르게 하는 가벼운 선택이면 바텀시트 |
| 툴팁(FB-07) 대 코치마크(FB-08) | 항목 하나에 대한 보충 설명을 사용자가 요청할 때(가리키거나 초점) 보이면 툴팁, 처음 쓰는 사용자에게 화면 요소 하나를 강조해 먼저 안내하면 코치마크 |
| 인라인 오류(FB-06) 대 토스트(FB-01) | 오류가 특정 입력 필드에 속하면 그 필드 옆에 인라인 오류, 특정 필드가 없는 일시적 알림이면 토스트 |
| 뱃지(FB-09) 대 배너(FB-03) | 아이콘 옆에 개수 또는 새 항목 유무만 표시하면 뱃지, 문장으로 사정을 설명해야 하면 배너 |

## FB-01 토스트 (Toast)
- ID: FB-01
- Korean Name: 토스트
- English Name: Toast
- Category: Feedback & Notifications
- Definition: 방금 한 동작의 결과를 짧은 문구로 알리고 스스로 사라지는 비차단 메시지; 행동 단추 없음
- Purpose: 흐름을 끊지 않고 동작이 처리됐음을 확인시킴
- User Problem: 저장 또는 복사처럼 화면 변화가 작은 동작 뒤에 성공했는지 알기 어려움
- When to Use: 되돌릴 필요가 없는 가벼운 성공 확인; 사용자가 같은 화면에 계속 머무는 흐름; 놓쳐도 다른 조치가 필요하지 않은 안내
- When Not to Use: 되돌리기 같은 행동이 필요하면 FB-02; 계속 보여야 하는 사정은 FB-03; 필드 입력 오류는 FB-06; 결정을 받아야 하면 FB-04
- Interaction Behavior: 동작 직후 나타나 5초 뒤 스스로 사라짐 (DF-01); 포인터 올림, 초점, 터치 중, 창 비활성에서는 타이머를 멈춤 (DF-04); 한 번에 하나만 보이고 새 메시지는 이전 것을 대체 (DF-05); 오류는 자동으로 닫지 않음 (DF-03)
- Required States: 표시 중, 일시정지, 사라짐, 대체됨, 오류 표시 (아래 `상태 표`)
- Visual Guidelines: 어두운 알약 모양 안에 짧은 문구 한 줄; 글자 대비 4.5:1 이상(WCAG 1.4.3); 하단 탭바 및 입력 단추를 가리지 않는 위치
- Accessibility: `role="status"`(aria-live polite)로 읽힘; 시간 제한이므로 일시정지 및 연장 수단을 둠 (WCAG 2.2.1, DF-04); 중요한 정보는 토스트에만 두지 않음
- Responsive Considerations: 좁은 화면에서 줄바꿈으로 폭 안에 수용; 소프트 키보드 및 하단 탐색에 가리지 않게 위치 조정
- Implementation Guidelines: 알림 영역(live region)을 먼저 화면에 두고 내용만 바꿔야 읽힘; 타이머는 닫힐 때 반드시 정리; 연속 호출은 대체 또는 대기열 중 하나로 일관되게 처리
- Common Mistakes: 행동 단추를 넣고 짧은 시간 안에 누르게 함; 중요한 오류를 토스트로만 알림; 화면 이동 시 사라져 읽지 못함
- Related Patterns: FB-02, FB-03, FB-06
- Reference Image: 장면: "저장하기" 단추 아래 어두운 알약 모양 메시지 "찜 목록에 저장했어요"

### FB-01 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 표시 중 | 동작 결과가 도착함 | 알림 영역 `role="status"` (aria-live polite) 의 텍스트가 새 문구로 바뀜 | 알약 안에 아이콘 및 문구 한 줄이 나타남. reduced-motion 이면 투명도 변화만 (DF-20) | 일시정지, 사라짐, 대체됨 |
| 일시정지 | 포인터를 올림, 초점이 토스트 안 컨트롤에 있음, 터치 중, 창이 비활성 (DF-04) | 변화 없음 | 남은 시간이 멈추고 모양 유지 | 표시 중 (조건이 풀리면 남은 시간부터 재개) |
| 사라짐 | DF-01 시간이 지남 또는 닫기 | 알림 영역이 비워짐 (영역 자체는 DOM 에 남김) | 사라지고 타이머 정리 | 없음 |
| 대체됨 | 새 메시지가 도착함 (DF-05) | 알림 영역 텍스트가 새 문구로 바뀜 | 문구가 교체되고 타이머를 처음부터 다시 시작 | 표시 중 |
| 오류 표시 (토스트를 쓸 수밖에 없을 때) | 동작이 실패함 | `role="alert"` | 아이콘 및 문구로 오류임을 표시 (색만으로 구분 금지, WCAG 1.4.1). 자동으로 닫지 않음 (DF-03) | 사용자가 닫음 또는 원인 해소 |

### FB-01 토스트 정본 규칙
| 항목 | 규칙 | 값 |
|---|---|---|
| 자동 닫힘 | 정보성은 자동으로 닫음. 오류는 자동으로 닫지 않고 가능하면 토스트 대신 FB-06 또는 FB-03 에 표시 | DF-01, DF-03 |
| 시간 | 정보성 5초. 행동 단추가 있으면 FB-02 | DF-01, DF-02 |
| 일시정지 | 포인터 올림, 초점 안에 있음, 터치 중, 창 비활성 | DF-04 |
| 대체 및 쌓기 | 정보성은 한 번에 하나이고 새 메시지가 대체. 쌓기 컨테이너는 오류 토스트가 불가피한 경우에만 | DF-05 |
| 초점 | 나타날 때 초점을 가져오지 않음. 닫힐 때 초점이 `body` 로 떨어지지 않게 직전 위치로 돌려보냄 | Chrome modern-web-guidance 확인 |
| 같은 규칙을 쓰는 파일 | `interaction-rules.md`, `modern-web.md` 는 이 표를 참조함 | |

## FB-02 스낵바 (Snackbar)
- ID: FB-02
- Korean Name: 스낵바
- English Name: Snackbar
- Category: Feedback & Notifications
- Definition: 동작 결과를 알리면서 짧은 행동 단추(되돌리기 등)를 함께 주는 화면 하단 막대 메시지
- Purpose: 실수로 한 동작을 곧바로 되돌릴 기회를 줌
- User Problem: 삭제 같은 동작이 되돌릴 수 없어 보여 확인 대화 상자가 반복됨
- When to Use: 삭제 또는 이동처럼 되돌릴 수 있는 동작 직후; 행동 하나만 제안할 때
- When Not to Use: 알리기만 하면 FB-01; 되돌릴 수 없는 파괴적 동작은 사전 확인 FB-04; 행동이 둘 이상이면 FB-05
- Interaction Behavior: 동작 직후 하단에 나타나 10초 뒤 사라지고 그때 삭제가 확정됨 (DF-02); 행동 단추를 누르면 동작을 취소하고 막대가 닫힘; 상태별 처리는 `상태 표` 및 `키보드 초점 처리` 를 따름
- Required States: 대기, 확정, 취소, 이탈, 대체됨 (아래 `상태 표`)
- Visual Guidelines: 어두운 막대, 왼쪽 문구, 오른쪽 행동 단추("되돌리기"); 문구 4.5:1(WCAG 1.4.3); 행동 단추 터치 목표 44x44pt(Apple HIG) 또는 48x48dp(Material Design)
- Accessibility: `role="status"`; 행동 단추는 키보드로 도달해야 함(WCAG 2.1.1); 사라지는 시간이 짧으면 키보드 사용자가 놓침, 시간 조절 필요(WCAG 2.2.1); 화면 안 되돌리기 경로 (휴지통, 실행 취소 단추, 항목 메뉴) 필수
- Responsive Considerations: 좁은 화면에서는 폭 전체, 넓은 화면에서는 모서리에 붙여 폭 제한; 하단 탐색 위에 배치
- Implementation Guidelines: 서버에 `삭제 예정` 으로 먼저 보내고 DF-02 시간이 지나면 확정하는 구조 (탭 닫기 및 다른 기기 조회에서 안전). 확정을 클라이언트에서 지연하는 구조를 쓰면 `상태 표` 의 이탈 처리를 따로 구현; 사라지는 중에도 행동 단추가 눌릴 수 있게 타이머 정리; 키보드 초점은 호출한 단추 근처에 유지
- Common Mistakes: 행동 단추가 없는데 스낵바로 둠(이 스킬의 구분 규칙: 행동이 없으면 토스트. 디자인 시스템에 따라 스낵바의 행동 단추를 선택 사항으로 두기도 하므로 프로젝트의 이름 규칙을 따름); 되돌릴 시간이 너무 짧음; 되돌리기를 눌러도 실제로 복구되지 않음
- Related Patterns: FB-01, FB-04, FB-05
- Reference Image: 장면: 화면 아래 어두운 막대 "일정을 삭제했어요" 및 행동 "되돌리기"

### FB-02 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 대기 | 되돌릴 수 있는 삭제나 이동을 실행함 | 알림 영역 `role="status"` 에 `일정을 삭제했어요` 문구 갱신. 되돌리기 단추는 같은 컨테이너 안 | 항목이 목록에서 즉시 사라지고 하단 막대가 나타남. 서버에는 `삭제 예정` 으로 먼저 보냄 (복구 가능 기간 = DF-02 시간 이상) | 확정, 취소, 이탈, 대체됨 |
| 확정 | DF-02 시간이 지남 (타이머 일시정지 DF-04 해제 후) | 알림 영역이 비워짐 | 막대가 사라짐. 화면 안 되돌리기 경로 (휴지통, 실행 취소 단추, 항목 메뉴) 가 남아 있어야 함 | 종료 |
| 취소 | 되돌리기 단추 실행 (키보드 Enter 또는 Space 포함) | 알림 영역에 `삭제를 취소했어요` | 항목이 원래 위치로 돌아오고 막대가 닫힘. 서버에 복구 요청을 보내고 실패하면 오류를 알림 | 종료 (복구 실패 시 대기로 돌아가지 않고 오류 표시) |
| 이탈: 화면 이동 | 대기 중에 다른 화면으로 이동함 | 변화 없음 | 스낵바 호스트를 앱 루트에 두어 남은 시간 동안 유지함. 되돌리기는 이동한 화면에서도 가능 | 확정 또는 취소 |
| 이탈: 탭 닫기 또는 새로고침 | 대기 중에 탭을 닫거나 새로고침함 | 해당 없음 | 서버에 이미 `삭제 예정` 으로 보냈으므로 추가 동작 없음. 이 구조를 쓰지 않고 확정을 지연했다면 `pagehide` 에서 확정 요청을 보냄 (`fetch` 의 `keepalive` 또는 `navigator.sendBeacon`, 일반 권고) | 확정 |
| 이탈: 다른 기기 조회 | 대기 중에 같은 계정의 다른 기기가 목록을 조회함 | 해당 없음 | `삭제 예정` 항목은 서버가 이미 숨김. 되돌리기는 시작한 기기에서만 가능 | 확정 또는 취소 |
| 대체됨 | 대기 중에 새 스낵바가 필요한 동작이 일어남 (DF-05) | 알림 영역 텍스트가 새 문구로 바뀜 | 앞의 삭제는 즉시 확정되고 새 스낵바가 표시됨. 앞의 되돌리기는 화면 안 경로로만 가능 | 대기 (새 항목) |

### FB-02 키보드 초점 처리
| 문제 | 처리 | 근거 |
|---|---|---|
| `role="status"` 영역은 읽히지만 안의 단추에는 초점이 가지 않음 | 문구는 `role="status"` 로 읽게 하고, 되돌리기 단추는 같은 컨테이너에 두되 초점을 자동으로 가져오지 않음. 키보드로 최신 스낵바로 이동하는 단축키 (F6) 를 제공 | 초점을 가져오지 않는 것 및 포커스 복귀: Chrome modern-web-guidance 확인. F6 단축키: 일반 권고, 출처 미확인 |
| 초점이 단추에 있는 동안 막대가 사라짐 | 초점이 막대 안에 있으면 타이머를 멈추고 (DF-04) 초점이 떠나면 재개 | Chrome modern-web-guidance 확인 |
| 막대가 사라진 뒤 초점이 `body` 로 떨어짐 | 사라질 때 초점을 직전 위치로 돌려보냄 | Chrome modern-web-guidance 확인 |
| 시간 제한 안에 키보드 사용자가 되돌리지 못함 | 화면 안 되돌리기 경로를 필수로 둠 (휴지통, 실행 취소 단추, 항목 메뉴) | WCAG 2.2.1 확인 (시간 제한은 끄기, 조정, 연장 중 하나 필요) |

## FB-03 배너 (Banner)
- ID: FB-03
- Korean Name: 배너
- English Name: Banner
- Category: Feedback & Notifications
- Definition: 화면 위쪽 문서 흐름 안에 표시되어 상태 또는 공지를 알리고 사용자가 닫을 때까지 남는 띠 형태 메시지
- Purpose: 현재 화면 전체에 해당하는 사정을 지속적으로 알림
- User Problem: 마감, 점검, 연결 상태 같은 정보를 놓치면 불이익이 생기는데 일회성 메시지는 금방 사라짐
- When to Use: 화면 전체에 적용되는 상태(마감 임박, 점검 예정, 오프라인); 사용자가 닫거나 해결할 때까지 필요한 안내
- When Not to Use: 동작 결과 확인은 FB-01; 개수만 알리면 FB-09; 결정을 받아야 하면 FB-04; 필드에 속한 오류는 FB-06
- Interaction Behavior: 화면 진입 또는 상태 변화 시 위쪽에 나타남; 닫기(X)로 닫음; 닫아도 되는 정보는 닫으면 같은 화면에서 다시 뜨지 않음; 해결되면 스스로 사라짐
- Required States: 표시 중, 닫힘, 해결되어 제거됨, 심각도 구분 (아래 `상태 표`)
- Visual Guidelines: 화면 위 띠, 정보는 파란 계열; 문구 4.5:1(WCAG 1.4.3); 닫기 단추 터치 목표 44x44pt(Apple HIG) 또는 48x48dp(Material Design)
- Accessibility: 일반 정보는 `role="status"`, 즉시 알려야 하는 오류는 `role="alert"`; 닫기 단추는 `aria-label`로 이름 제공; 닫기 단추 초점이 완전히 가려지지 않음(WCAG 2.4.11)
- Responsive Considerations: 좁은 화면에서 문구가 길면 줄바꿈 또는 말줄임 후 상세 링크; 위쪽 고정 헤더와 겹치지 않게 헤더 바로 아래에 배치하고 한 화면에 하나만 표시
- Implementation Guidelines: 문서 흐름 안에 넣어 아래 콘텐츠를 밀어 내림(고정 위치로 가리지 않음); 닫힘 상태는 세션 동안 저장하고 `다시 보지 않기` 를 고르면 영구 저장 (DF-45); 한 화면에 여러 개를 쌓지 않음
- Common Mistakes: 닫기 단추가 없어 항상 남음; 자동으로 사라지게 해서 놓침; 여러 배너가 쌓여 본문이 밀림
- Related Patterns: FB-01, FB-09, ES-04
- Reference Image: 장면: 화면 위 파란 정보 띠 "쿠폰 마감이 3일 남았어요" 및 닫기(X)

### FB-03 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 표시 중 | 화면 진입 또는 상태 변화 | 정보는 `role="status"`, 즉시 알릴 오류는 `role="alert"` | 화면 위 문서 흐름 안에 띠가 나타나 아래 내용을 밀어 내림 | 닫힘, 해결되어 제거됨 |

| 해결되어 제거됨 | 원인이 해소됨 (온라인 복귀 등) | 알림 영역 갱신 (필요하면 `해결됐어요` 한 번) | 띠가 스스로 사라짐 | 없음 |
| 심각도 구분 | 정보, 경고, 오류 중 하나로 분류됨 | 정보 `role="status"`, 오류 `role="alert"` | 아이콘 및 문구로 구분 (색만으로 구분 금지, WCAG 1.4.1) | 표시 중 |

## FB-04 모달 (Modal dialog)
- ID: FB-04
- Korean Name: 모달
- English Name: Modal dialog
- Category: Feedback & Notifications
- Definition: 나머지 화면을 막고 사용자의 결정 또는 확인을 받아야 진행되는 대화 상자
- Purpose: 되돌리기 어렵거나 중요한 결정 앞에서 사용자의 주의를 모음
- User Problem: 비용 발생 또는 삭제 같은 동작이 의도 없이 실행될 수 있음
- When to Use: 결제 또는 영구 삭제처럼 되돌리기 어려운 동작의 확인; 진행 전 필수 정보 한 가지를 받아야 할 때
- When Not to Use: 단순 안내는 FB-01 또는 FB-03; 되돌릴 수 있는 동작은 실행 후 FB-02; 항목 선택 목록은 FB-05; 긴 입력은 별도 화면
- Interaction Behavior: 열리면 뒤 화면이 어두워지고 조작 불가; 초점이 대화 상자 안에 갇힘; Esc 및 닫기 단추로 닫음; 닫으면 연 단추로 초점이 돌아감
- Required States: 열림, 처리 중, 닫힘, 확정 및 취소 단추 구분 (아래 `상태 표`)
- Visual Guidelines: 제목, 보조 문구, 취소 및 확정 단추 두 개; 파괴적 확정 단추는 색 및 문구로 구분(WCAG 1.4.1); 단추 문구는 동사로 구체적으로
- Accessibility: 네이티브 `<dialog>` + `showModal()` 이 기본이며 `role="dialog"`, `aria-modal`, 수동 초점 가두기를 직접 쓰지 않음 (브라우저가 제공, DF-07); `aria-labelledby` 로 이름 제공; 열릴 때 안으로 초점 이동, 닫을 때 호출한 요소로 복귀; Esc 닫기; 키보드 함정 아님(WCAG 2.1.2); 사용자 정의 대화 상자일 때만 `role="dialog"`, `aria-modal="true"`, 초점 가두기를 직접 구현
- Responsive Considerations: 좁은 화면에서는 폭을 줄여 가운데 유지 또는 아래 시트 형태로 바꾸되 같은 역할 유지; 내용이 길면 대화 상자 안에서만 스크롤
- Implementation Guidelines: `<dialog>`의 `showModal()` 사용 (DF-07); 뒤 화면 `inert` 는 네이티브가 처리하므로 직접 토글하지 않음; 배경 스크롤은 `dialog:modal { overscroll-behavior: contain }` 및 `dialog::backdrop { overflow: hidden; overscroll-behavior: contain }` 를 둘 다 둠 (`::backdrop` 의 `overflow` 기본값이 `visible` 이라 `overflow: hidden` 이 없으면 `overscroll-behavior` 가 무시됨), `html` 및 `body` 의 `overflow: hidden` 은 쓰지 않음; 파괴 동작 확인은 취소 단추에 `autofocus`; 중첩 모달 금지
- Common Mistakes: 가벼운 안내에도 모달을 씀; 취소 및 확정 위치 및 문구가 모호함; 초점이 안 가둬져 뒤 화면 조작됨; 배경 클릭 닫기를 막지도 허용하지도 않고 방치
- Related Patterns: FB-02, FB-05, DP-09
- Reference Image: 장면: 어두운 배경 위 대화 상자 "결제할까요?", 보조 문구 "결제 후엔 취소 수수료가 있어요", 단추 "취소" 및 "결제"

### FB-04 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 열림 | 확정이나 결정이 필요한 동작을 실행함 | 네이티브 `<dialog>` + `showModal()` 은 `role`, `aria-modal` 을 직접 쓰지 않음. 이름은 `aria-labelledby` (DF-07) | 뒤 화면이 어두워지고 조작 불가. 초점이 안으로 이동 | 처리 중, 닫힘 |
| 처리 중 | 확정 단추 실행 | 확정 단추 `aria-disabled="true"`, 진행 문구는 `role="status"` | 확정 단추 중복 누름 방지, 단추 안 진행 표시 (LD-06) | 닫힘 (성공), 열림 (실패, 오류 문구 표시) |
| 닫힘 | 취소 단추, Esc, 확정 성공 | 해당 없음 | 대화 상자가 사라지고 열었던 단추로 초점이 돌아가며 스크롤 위치가 변하지 않음 | 없음 |
| 확정 및 취소 구분 | 대화 상자 구성 시 | 파괴 동작은 취소 단추에 `autofocus` | 단추 문구가 동사로 구체적 (`취소`, `결제`). 파괴적 확정은 색 및 문구로 구분 (WCAG 1.4.1) | 열림 |

## FB-05 바텀시트 (Bottom sheet)
- ID: FB-05
- Korean Name: 바텀시트
- English Name: Bottom sheet
- Category: Feedback & Notifications
- Definition: 화면 아래에서 올라와 관련 동작 또는 선택지를 보여주는 패널
- Purpose: 한 손 조작 영역에서 동작 목록을 고르게 함
- User Problem: 항목마다 단추를 모두 두면 화면이 복잡하고, 전체 화면 전환은 과함
- When to Use: 항목에 대한 동작 여러 개(공유, 이름 바꾸기, 삭제); 비교적 짧은 선택 목록; 모바일 화면
- When Not to Use: 반드시 결정을 받아야 하는 확인은 FB-04; 알리기만 하면 FB-01; 긴 입력 및 복잡한 흐름은 별도 화면
- Interaction Behavior: 호출하면 아래에서 올라옴; 항목을 누르면 실행하고 닫힘; 손잡이 드래그, 바깥 누르기, 닫기 단추로 닫음; 드래그에는 단일 포인터 대안 제공(WCAG 2.5.7)
- Required States: 닫힘, 열림, 항목 눌림, 파괴적 항목 구분, 처리 중 (아래 `상태 표`)
- Visual Guidelines: 위쪽에 손잡이, 항목 목록, 삭제 같은 파괴적 항목은 빨강; 항목 터치 목표 44x44pt(Apple HIG) 또는 48x48dp(Material Design)
- Accessibility: 모달형이면 네이티브 `<dialog>` + `showModal()` 로 만들어 `role`, `aria-modal`, 초점 가두기를 직접 쓰지 않음 (DF-07; 사용자 정의 시트일 때만 `role="dialog"`, `aria-modal="true"`, 초점 가두기를 직접 구현); Esc 닫기, 닫은 뒤 초점 복귀; 손잡이 드래그만으로 닫는 경로 금지, 닫기 단추 제공(WCAG 2.5.7)
- Responsive Considerations: 넓은 화면에서는 작은 팝오버 또는 대화 상자 형태로 대체; 키보드가 올라와도 항목이 가려지지 않게 높이 제한
- Implementation Guidelines: 사용자 정의 시트이면 열려 있는 동안 뒤 화면 `inert` (네이티브 `<dialog>` 는 필요 없음); 높이는 내용에 맞추되 화면 높이의 상한을 둠; 닫힘 애니메이션에서 `prefers-reduced-motion` 존중
- Common Mistakes: 제스처로만 닫을 수 있음; 목록이 길어 시트가 거의 전체 화면을 덮음; 파괴적 항목을 첫 위치에 둠
- Related Patterns: FB-04, IC-02, GS-02
- Reference Image: 장면: 아래에서 올라온 시트, 손잡이, 항목 "공유하기", "이름 바꾸기", "삭제하기"(빨강)

| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 닫힘 | 초기 상태 또는 닫기 동작 | 해당 없음 | 시트가 보이지 않음 | 열림 |
| 열림 | 항목의 더보기 단추 실행 | 모달형이고 네이티브 `<dialog>` 이면 `role`, `aria-modal` 을 직접 쓰지 않음 (DF-07). 사용자 정의 시트일 때만 `role="dialog"`, `aria-modal="true"` | 아래에서 올라오고 손잡이가 보임. reduced-motion 이면 투명도 변화만 | 항목 눌림, 닫힘 |
| 항목 눌림 | 항목 하나를 실행 | 눌린 항목 상태는 `aria-busy` 또는 단추 비활성으로 표시 | 눌린 항목이 강조되고 처리 시작 | 처리 중, 닫힘 |

## FB-06 인라인 오류 (Inline error)
- ID: FB-06
- Korean Name: 인라인 오류
- English Name: Inline error
- Category: Feedback & Notifications
- Definition: 오류가 난 입력 필드 바로 옆 또는 아래에 오류 원인과 해결 방법을 보이는 문구
- Purpose: 어느 필드가 왜 틀렸는지 그 자리에서 알림
- User Problem: 화면 위나 토스트의 일반 오류는 어느 필드인지 알려주지 못함
- When to Use: 입력 형식 오류, 필수 누락 등 특정 필드에 속한 오류; 제출 후 또는 필드를 벗어날 때
- When Not to Use: 특정 필드가 없는 일시 알림은 FB-01; 화면 전체 상태는 FB-03; 서버 장애 화면은 ES-08
- Interaction Behavior: 오류가 확인되는 시점에 필드 아래에 문구가 나타남; 고쳐서 유효해지면 사라짐; 제출 후 첫 오류 필드로 초점 이동 가능
- Required States: 오류 없음, 오류, 수정 중, 해결됨, 여러 오류 (아래 `상태 표`)
- Visual Guidelines: 빨간 테두리 및 필드 아래 문구; 빨강만으로 알리지 않고 아이콘 또는 문구 병행(WCAG 1.4.1); 문구 4.5:1(WCAG 1.4.3), 테두리 3:1(WCAG 1.4.11)
- Accessibility: 필드에 `aria-invalid="true"` 및 오류 문구를 `aria-describedby`로 연결; 오류 식별(WCAG 3.3.1) 및 수정 제안(WCAG 3.3.3); 즉시 알릴 오류는 `role="alert"`; 레이블 유지(WCAG 3.3.2)
- Responsive Considerations: 좁은 화면에서 문구가 필드 폭 안에서 줄바꿈; 오류 문구 때문에 아래 단추가 밀려도 겹치지 않음
- Implementation Guidelines: 입력 도중 타이핑마다 오류를 띄우지 않고 필드를 벗어날 때 또는 제출 때 검증; 오류 문구에 원인 및 해결법 포함; 법적 및 금융 거래는 제출 전 확인 단계(WCAG 3.3.4)
- Common Mistakes: "오류가 발생했습니다"처럼 원인이 없는 문구; 필드 위 토스트로만 알림; 오류 상태가 색만으로 구분됨
- Related Patterns: FB-01, FM-01, ES-08
- Reference Image: 장면: 이메일 필드(값 "user@mail") 빨간 테두리, 아래 문구 "이메일 형식을 확인해 주세요"

### FB-06 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 오류 없음 | 초기 상태 | `aria-invalid` 는 `false` 로 시작 | 기본 테두리 | 오류 |
| 오류 | 필드를 벗어남 또는 제출 (입력 도중에는 띄우지 않음) | `aria-invalid="true"`, 오류 문구를 `aria-describedby` 로 연결. 즉시 알릴 오류는 `role="alert"` | 빨간 테두리 및 필드 아래 문구. 아이콘 또는 문구 병행 (WCAG 1.4.1) | 수정 중 |
| 수정 중 | 오류 필드에 다시 입력함 | `aria-invalid` 유지 (확정 전) | 입력한 값을 지우지 않고 남김 | 해결됨, 오류 |
| 해결됨 | 값이 유효해짐 | `aria-invalid="false"`, 오류 문구 제거 | 테두리와 문구가 기본으로 돌아감 | 오류 없음 |
| 여러 오류 | 제출 시 둘 이상 오류 | 요약 영역 `role="alert"` 또는 첫 오류 필드로 초점 이동 | 모든 오류를 각 필드 아래에 표시 | 수정 중 |

## FB-07 툴팁 (Tooltip)
- ID: FB-07
- Korean Name: 툴팁
- English Name: Tooltip
- Category: Feedback & Notifications
- Definition: 요소에 가리키거나 초점이 갈 때 나타나는 짧은 보충 설명 말풍선
- Purpose: 아이콘 또는 용어의 의미를 필요한 사람에게만 보충
- User Problem: 용어 뜻이나 아이콘 의미를 모르는데 화면에 설명을 늘 두면 복잡해짐
- When to Use: 용어 또는 아이콘 하나에 대한 한두 문장 보충; 없어도 핵심 작업이 가능한 부가 정보
- When Not to Use: 처음 쓰는 사용자 안내는 FB-08; 필수 정보 및 오류는 화면에 직접 표시; 터치 전용 화면의 유일한 설명 수단으로 사용 금지; 긴 설명은 별도 안내
- Interaction Behavior: 가리키거나 초점이 오면 나타남; 가리킨 채로 말풍선 위로 이동해도 유지됨; 벗어나면 닫힘; Esc로 닫음
- Required States: 숨김, 표시, 닫힘, 터치 환경 대안 (아래 `상태 표`)
- Visual Guidelines: 정보 아이콘 위의 작은 말풍선; 문구 4.5:1(WCAG 1.4.3); 대상 요소를 가리지 않는 위치; 화면 가장자리에서 잘리지 않게 자동 반전
- Accessibility: `role="tooltip"` 및 `aria-describedby`로 대상과 연결; hover 또는 focus로 뜬 내용은 닫을 수 있고 가리킬 수 있고 유지돼야 함(WCAG 1.4.13); 키보드 초점으로도 열림(WCAG 2.1.1)
- Responsive Considerations: 터치 화면은 hover가 없으므로 정보 아이콘을 누르면 열리는 방식 제공; 대상 목표 크기 24x24 CSS px 이상(WCAG 2.5.8)
- Implementation Guidelines: 대상은 초점을 받을 수 있는 `<button>` 등으로 하고 `aria-label` 제공; 위치는 뷰포트 기준으로 계산해 잘림 방지; 말풍선 안에 링크 및 단추를 넣지 않음
- Common Mistakes: hover에서만 열려 키보드 사용자가 못 봄; 마우스를 말풍선으로 옮기면 사라짐; 필수 설명을 툴팁에 숨김
- Related Patterns: FB-08, IC-04, FM-01
- Reference Image: 장면: "이번 달 저축률" 옆 정보 아이콘 위 말풍선 "최근 3개월 지출 기준이에요"

### FB-07 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 숨김 | 초기 상태 | 대상에 `aria-describedby` 로 연결해 둠 | 보이지 않음 | 표시 |
| 표시 | 포인터를 올림 또는 키보드 초점 | `role="tooltip"` | 대상 옆에 말풍선. 가장자리에서 자동 반전 | 닫힘 |
| 닫힘 | 포인터가 벗어남, 초점이 벗어남, Esc | 해당 없음 | 말풍선이 사라짐. 포인터를 말풍선 위로 옮겨도 유지 (WCAG 1.4.13) | 숨김 |
| 터치 환경 대안 | 터치 화면에서 정보 아이콘을 누름 | 누르는 단추는 `aria-expanded` 로 열림 상태 표시 | 누르면 열리고 다시 누르거나 바깥을 누르면 닫힘 | 닫힘 |

## FB-08 코치마크 (Coach mark)
- ID: FB-08
- Korean Name: 코치마크
- English Name: Coach mark
- Category: Feedback & Notifications
- Definition: 어두운 덮개 위에 화면 요소 하나를 강조하고 사용법을 안내하는 첫 사용 안내
- Purpose: 새 기능 또는 핵심 단추의 위치 및 역할을 처음 한 번 알림
- User Problem: 처음 쓰는 사용자가 핵심 단추를 발견하지 못함
- When to Use: 처음 방문 시 핵심 동작 한두 개를 알려야 할 때; 새로 추가된 기능 안내
- When Not to Use: 항상 필요한 설명은 화면에 직접 표시; 요소 하나에 대한 부가 설명은 FB-07; 반복 노출되는 권유는 DP-09 로 변질되므로 금지
- Interaction Behavior: 처음 진입 시 덮개 및 강조가 나타남; "알겠어요" 또는 닫기로 종료; 다시 보지 않게 기록; 건너뛰기 가능
- Required States: 미표시, 표시 중, 확인 후 종료, 이미 본 상태, 여러 단계 (아래 `상태 표`)
- Visual Guidelines: 어두운 덮개, 강조된 요소 하나(+ 단추), 안내 문구 및 확인 단추; 안내 문구 4.5:1(WCAG 1.4.3); 강조 요소를 가리지 않음
- Accessibility: 덮개 중에는 네이티브 `<dialog>` 이면 `role`, `aria-modal` 을 직접 쓰지 않고 (DF-07), 사용자 정의일 때만 `role="dialog"`, `aria-modal="true"`, 초점 가두기를 직접 구현; Esc 닫기; 안내를 건너뛸 수 있어야 하며 키보드로 확인 단추에 도달(WCAG 2.1.1); 닫은 뒤 초점 복귀
- Responsive Considerations: 화면 크기에 따라 강조 요소 위치가 바뀌므로 위치를 요소에서 계산; 요소가 화면 밖이면 스크롤하거나 안내 생략
- Implementation Guidelines: 이미 본 여부를 저장(사용자 단위가 이상적)하고 로드 시 확인; 대상 요소가 없으면 코치마크를 띄우지 않음; 사용자 정의 덮개이면 덮개 뒤 화면은 `inert` (네이티브 `<dialog>` 는 필요 없음)
- Common Mistakes: 매번 다시 나옴; 한 번에 여러 개를 연속 노출; 건너뛰기가 없어 사용자를 가둠
- Related Patterns: FB-07, FB-04, ES-01
- Reference Image: 장면: 어두운 덮개 위에 + 단추만 강조, 문구 "여기서 계좌를 연결해요", 단추 "알겠어요"

### FB-08 상태 표
| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 미표시 | 대상 요소가 없거나 이미 봤음 | 해당 없음 | 표시하지 않음 | 표시 중 |
| 표시 중 | 처음 방문하고 대상 요소가 있음 | 네이티브 `<dialog>` 이면 `role`, `aria-modal` 을 직접 쓰지 않음 (DF-07). 사용자 정의일 때만 `role="dialog"`, `aria-modal="true"` | 어두운 덮개 위에 요소 하나가 강조됨 | 확인 후 종료, 건너뛰기 |
| 확인 후 종료 | `알겠어요` 실행 또는 건너뛰기 | 해당 없음 | 덮개가 사라지고 초점이 이전 위치로 돌아감 | 이미 본 상태 |
| 이미 본 상태 | 종료 기록이 저장됨 | 해당 없음 | 다시 표시하지 않음 | 없음 |
| 여러 단계 | 안내가 둘 이상 이어짐 | 현재 단계를 `aria-label` 로 알림 (예: `2 / 3`) | 현재 위치 표시. 다음 및 건너뛰기를 항상 제공 | 표시 중 (다음), 확인 후 종료 |

## FB-09 뱃지 (Badge)
- ID: FB-09
- Korean Name: 뱃지
- English Name: Badge
- Category: Feedback & Notifications
- Definition: 아이콘 모서리에 숫자 또는 점으로 새 항목 유무 및 개수를 표시하는 작은 표식
- Purpose: 확인하지 않은 새 항목이 있음을 한눈에 알림
- User Problem: 알림이나 메시지가 쌓였는지 열어 보지 않으면 알 수 없음
- When to Use: 읽지 않은 알림, 메시지 등 개수가 의미 있을 때(숫자); 새 항목 유무만 알리면 될 때(점)
- When Not to Use: 사정을 문장으로 설명해야 하면 FB-03; 동작 결과 확인은 FB-01; 계속 변하는 수치 전체를 표시하는 용도 금지
- Interaction Behavior: 새 항목이 생기면 나타나고 개수가 갱신됨; 해당 목록을 열어 확인하면 사라지거나 줄어듦; 뱃지 자체는 동작을 갖지 않고 부모 아이콘 단추가 동작
- Required States: 없음, 점, 숫자, 큰 숫자, 확인 후 해제 (아래 `상태 표`)
- Visual Guidelines: 종 아이콘에 숫자 3, 말풍선 아이콘에 빨간 점; 숫자 4.5:1(WCAG 1.4.3), 뱃지 및 배경의 구분 3:1(WCAG 1.4.11); 색만으로 의미를 전하지 않음(WCAG 1.4.1)
- Accessibility: 뱃지 값을 부모 단추의 이름에 포함(예: "알림, 새 알림 3개"); 값이 바뀌면 `role="status"`로 알림; 점만 있는 뱃지도 텍스트 대안 제공(WCAG 4.1.2)
- Responsive Considerations: 아이콘 크기에 비례하되 숫자가 읽히는 최소 크기 유지; 자릿수가 늘어도 아이콘을 가리지 않음
- Implementation Guidelines: 시각 뱃지는 `aria-hidden`으로 두고 이름에 텍스트로 반영; 개수 갱신은 화면 진입 및 탭 복귀 때 하고 푸시 이벤트가 있으면 도착 시 갱신 (DF-46); 부모 단추 터치 목표 44x44pt(Apple HIG) 또는 48x48dp(Material Design)
- Common Mistakes: 뱃지만 있고 스크린리더에는 값이 없음; 확인해도 해제되지 않음; 모든 아이콘에 뱃지를 달아 변별력이 없어짐
- Related Patterns: FB-03, NV-01, IC-01
- Reference Image: 장면: 종 아이콘에 숫자 3, 말풍선 아이콘에 빨간 점, 문구 "새 알림이 3개 왔어요"

| 상태 | 진입 사건 | ARIA 값 | 보이는 변화 | 다음 상태 |
|---|---|---|---|---|
| 없음 | 새 항목이 없음 | 부모 단추 이름에 값 없음 | 뱃지가 보이지 않음 | 점, 숫자 |
| 점 | 새 항목이 있으나 개수는 필요 없음 | 부모 단추 이름에 `새 알림 있음` 반영. 시각 뱃지는 `aria-hidden` | 빨간 점 (색만으로 의미를 전하지 않음, WCAG 1.4.1) | 숫자, 확인 후 해제 |
