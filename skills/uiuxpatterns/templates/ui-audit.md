- 선택자: 문제 요소를 다시 찾을 수 있는 CSS 선택자 또는 접근성 트리 경로 (예: `form#signup button[type=submit]`). 코드 확인이면 `파일:줄`
- 위반 성공 기준: WCAG 2.2 성공 기준 번호 (예: `1.4.3`, `2.5.8`). 해당 기준이 없는 사용성 문제는 `해당 없음`. 번호와 이름은 `references/accessibility.md` 의 성공 기준 목록을 따른다
- 증거 파일: 캡처, 로그, 자동 검사 결과의 파일 경로 (예: `evidence/001-contrast.png`). 증거가 없으면 `없음` 이고 확인 방법을 `서술 기준` 으로 적는다
- 환경: 문제를 재현한 브라우저 및 버전, 보조기기 및 버전 (예: `Chrome 버전, NVDA 버전`). 자동 검사는 도구 규칙 ID 도 함께 적는다 (`references/quality-checklist.md` 13절)
- 사용자에게 발생하는 영향: 관찰한 사실만 적는다 (예: `오류 원인이 표시되지 않아 어느 필드를 고칠지 알 수 없음`)
- 검증 방법: 고친 뒤 무엇을 어떻게 확인하면 되는지
- 확인 방법: 이 문제를 `실사용 확인`, `코드 확인`, `자동 검사`, `서술 기준` 중 무엇으로 찾았는지
- 권장 패턴: 카탈로그에 없으면 `카탈로그 외`
