# Defaults (canonical table of default values)

Korean original: ../../references/defaults.md. IDs (DF-01 ~ DF-47) are identical. Evidence labels: `verified` = original source read, `summary only` = confirmed only from a summary, `general advice` = general UX advice whose source was not read (written in DF rows as `general recommendation, source unverified`). Other references are Korean for now and are linked by their Korean original path.

- Role: this table settles in one place the values that pattern files used to leave as `제품에서 정한다` (set per product). When asked to decide a value, use the default in this table right away
- How to use: `DF-nn` in a pattern file points to a row in this table. Use a different value only when the "may change when" condition applies, and write the changed value and the reason in one line in the design document
- Evidence labels: `verified` original source read, `summary only` confirmed only from a summary, `general advice` (`general recommendation, source unverified`) general UX advice whose source was not read. Numbers in general recommendations are provisional defaults that can be replaced by measurement
- Sources read (2026-11-25): Nielsen Norman Group three response-time limits, WCAG 2.2 Understanding documents (2.2.1, 2.2.2, 4.1.3), Material Web motion token file (`_md-sys-motion.scss` v0_192), Apple UIKit `UILongPressGestureRecognizer.minimumPressDuration`, Android `ViewConfiguration` and `PullToRefreshDefaults` reference docs, WAI-ARIA APG switch pattern, Chrome modern-web-guidance guidelines (motion, persistent-toast-notifications, switch, ime-safe-enter-submit, dialog)
- The Material 3 snackbar and badge specs and the Material 2 snackbar docs are script-rendered pages, so their body text could not be read. Those numbers are kept as general recommendations

## 1. Notifications (feedback.md)
| ID | Item | Default | Evidence | May change when | Patterns using it |
|---|---|---|---|---|---|
| DF-01 | Auto-close time of informational toast | 5 seconds | general recommendation, source unverified. Because it is a time limit, it must be extendable or switchable off: WCAG 2.2.1 verified | Lengthen if the text exceeds one line. May shorten if users can extend or turn it off in settings | FB-01 |
| DF-02 | Display and commit wait time of a snackbar with an action button | 10 seconds | general recommendation, source unverified | May shorten to 5 seconds if the screen has a separate undo path. If the undone result is tied to cost or external sending, do not use a snackbar, use FB-04 | FB-02 |
| DF-03 | Auto-close of error notifications | Do not auto-close. Keep until the user closes it or the cause is resolved | general recommendation, source unverified. Guideline that notifications needing immediate attention should use a component other than a toast: Chrome modern-web-guidance verified | For a background task where the same error repeats, merge into one line | FB-01, FB-03, FB-06 |
| DF-04 | Timer pause conditions | Pause while the pointer is over it, keyboard focus is inside the toast, touch is in progress, or the window is inactive; when released, resume from the remaining time | Pause when focus is on a control inside the toast: Chrome modern-web-guidance verified. The other three conditions are general recommendation, source unverified | None (the default means of meeting the time-adjustment requirement of WCAG 2.2.1) | FB-01, FB-02 |
| DF-05 | Simultaneous display and replacement rules for toasts | One informational toast at a time, a new message replaces the previous one. One snackbar at a time, when a new snackbar arrives, commit the previous deletion and replace. Do not use a toast for errors (DF-03). Stacking several in a toast container only when error toasts cannot be avoided | How to use a stacking container: Chrome modern-web-guidance verified. The replacement rule is general recommendation, source unverified | On a screen where results of different tasks arrive at once (e.g. multiple file uploads), allow stacking and make each item closable | FB-01, FB-02 |
| DF-06 | Badge number cap | `99+` | general recommendation, source unverified | `999+` if the badge area is wide enough that three digits do not overlap | FB-09, NV-01 |
| DF-07 | Implementation when a modal is needed for a notification | Native `<dialog>` + `showModal()`. Do not hand-write `role="dialog"`, `aria-modal`, focus trapping, `inert`, or `overflow: hidden` on `html` and `body`. For background scroll, set both `dialog:modal { overscroll-behavior: contain }` and `dialog::backdrop { overflow: hidden; overscroll-behavior: contain }` (the default `overflow` of `::backdrop` is `visible`, so without `overflow: hidden` the `overscroll-behavior` is ignored) | Chrome modern-web-guidance dialog guideline verified | Manual ARIA only for a custom dialog (a framework component that cannot use native `<dialog>`) | FB-04, FB-05, FB-08 |

## 3. Motion (motion.md)
| ID | Item | Default | Evidence | May change when | Patterns using it |
|---|---|---|---|---|---|
| DF-13 | Three motion durations | Short 100ms (press, hover, color change), medium 300ms (toggle, popover, movement of an element within the screen), long 500ms (full-screen transition, shared element). Define in one token location | Token values (short2 100ms, medium2 300ms, long2 500ms): Material Web `_md-sys-motion.scss` verified. The assignment of steps to uses is general recommendation, source unverified | One step longer if the travel distance covers most of the screen, one step shorter for small elements | MO-01 ~ MO-09 |
| DF-14 | Easing curves | Standard `cubic-bezier(0.2, 0, 0, 1)`, entering `cubic-bezier(0, 0, 0, 1)` (ease-out), exiting `cubic-bezier(0.3, 0, 1, 1)` (ease-in), emphasized entrance `cubic-bezier(0.05, 0.7, 0.1, 1)` | Material Web tokens (standard, standard-decelerate, standard-accelerate, emphasized-decelerate) verified | If a brand curve is defined, keep the token names and replace only the values | MO-01 ~ MO-04 |
| DF-15 | Exit duration | One step shorter than the entrance of the same element (for a 300ms medium entrance, a 100ms exit) | general recommendation, source unverified | For a transition where the exit overlaps the next screen's entrance, the same duration as the entrance | MO-01, MO-02 |
| DF-16 | Staggered entrance interval | 50ms stagger per item, overall cap 500ms (the long step of DF-13). If the cap is exceeded, show the earlier items grouped | 50ms is a token value (short1), the stagger and cap rule is general recommendation, source unverified | If there are 5 items or fewer, the stagger may be raised to 100ms | MO-05 |
| DF-17 | Spring values | Use the default spring values of the motion library in use as they are, without tuning. Use springs only for movement that inherits the release velocity, and time-based curves (DF-14) for the rest | general recommendation, source unverified | When a brand motion guide sets the values | MO-03 |
| DF-18 | Screen transition travel distance and fade | Travel distance 30px, with fade, duration is the medium step of DF-13. One direction rule (forward from the right, back from the left) for the whole app | general recommendation, source unverified | For shared-element transitions, compute the travel distance from the element position | MO-07 |
| DF-19 | Zoom transition scope on wide screens | In the desktop range (at or above the project's largest breakpoint), zoom a panel instead of the full screen | general recommendation, source unverified | A screen whose purpose is full screen, such as an image viewer | MO-08 |
| DF-20 | reduced-motion handling | Turn off movement, scaling, rotation and endlessly looping animation, and keep opacity and color changes. Do not use a global `animation-duration: 0.01ms` | Chrome modern-web-guidance motion guideline verified | For an element that conveys essential information only through motion, provide an alternative that gives the same information in the static state | MO-01 ~ MO-09, LD-01 ~ LD-09 |

## 4. Loading and input (loading.md, ai-interfaces.md, forms.md)
| ID | Item | Default | Evidence | May change when | Patterns using it |
|---|---|---|---|---|---|
| DF-21 | Wait time bands | Within 0.1 seconds: result immediately. 0.1 to 1 second: pressed state only, no loading indicator. 1 second or more: spinner or skeleton (shown after a delay). 2 seconds or more: add text explaining what is being done. 10 seconds or more: a means to cancel, and percent or a progress bar if measurable. The canonical band table is in loading.md | The 0.1 second, 1 second, 10 second limits, percent and a means to stop at 10 seconds or more, and that percent can be excessive in the 2 to 10 second band: NN/g verified. The 2 second text criterion is general recommendation, source unverified | For a repeated task where the delay recurs right after each press, consider optimistic updates (LD-08) instead of shortening the delay | LD-01 ~ LD-09 |
| DF-22 | Minimum display time of a loading indicator | Once shown, keep for 0.5 seconds or more (to prevent flicker) | general recommendation, source unverified | If the response has already arrived and the indicator would show for under 0.5 seconds, replace immediately | LD-01, LD-02, LD-09 |
| DF-23 | Transition from skeleton to real content | Fade of the short step of DF-13 (100ms), fixed area size. Under reduced-motion, replace immediately | The time is DF-13, the fixed-size principle is in loading.md. The transition method is general recommendation, source unverified | Image blur-up uses the medium step of DF-13 | LD-02, LD-07 |
| DF-24 | Debounce time | Search query auto-request 300ms, no request during Hangul composition, request after `compositionend` | 300ms is general recommendation, source unverified. Handling during composition is DF-27 | 500ms for an API with high call cost, 150ms for client-only use such as list filtering | FM-01 |
| DF-25 | AI first-response limit time | 30 seconds. If exceeded, switch to error guidance with a retry button | general recommendation, source unverified. A means to cancel is needed at 10 seconds or more: NN/g verified (DF-21) | For models with long reasoning time, follow the upper limit the server reports | AI-01 |
| DF-26 | File attachment limit values | Do not write numbers directly on screen: fetch the server policy values and show them in one line as `format list, maximum size` | general recommendation, source unverified | If the server does not provide values, the values agreed with the server owner | AI-08 |
| DF-27 | Enter during Hangul input | If `e.isComposing \|\| e.keyCode === 229`, do not submit. In React, `e.nativeEvent.isComposing`. Send search requests after `compositionend`, and compute character count and `maxlength` after composition is committed | The `isComposing` and `keyCode 229` code and the Safari `compositionend` ordering issue: Chrome modern-web-guidance ime-safe-enter-submit verified. React's `nativeEvent` is not in that guideline, so general recommendation, source unverified | None | FM-01, AI-07 |
| DF-28 | Switch markup | Use `<input type="checkbox" switch>` together with `role="switch"`. For unsupported browsers, load a polyfill via feature detection (`'switch' in HTMLInputElement.prototype`). `checked` if based on a native checkbox, `aria-checked` for a hand-made element. The label does not change when the state changes | The support limits of the `switch` attribute (not supported in Chrome, Edge, Firefox) and the polyfill rule: Chrome modern-web-guidance switch verified. `role="switch"`, `aria-checked`, Space key: WAI-ARIA APG verified. Per-browser screen reader output could not be read, so it is not written | None | FM-04 |
| DF-29 | When a slider value takes effect | A value that changes only on screen and is reversible (brightness preview) is applied immediately while moving. A value with server save or cost is committed on release | general recommendation, source unverified | None | FM-07 |

## 5. Selection criteria and composition (decision-framework.md, forms.md, ai-interfaces.md, navigation.md, icon-terminology.md, empty-states.md)
| ID | Item | Default | Evidence | May change when | Patterns using it |
|---|---|---|---|---|---|
| DF-30 | Number of steps at which to use a step indicator | 3 or more steps | general recommendation, source unverified | Use it even with 2 steps if each step is a different screen | LD-05 |
| DF-31 | Hierarchy depth at which to use breadcrumbs | 3 or more levels | general recommendation, source unverified | Even with a 2-level hierarchy, use a back button if there is only one path back to the parent list | NV-04, NV-09 |
| DF-32 | Radio and segmented control vs select | For 2 to 5 options, radio (in a form) or segmented control (view switching), for 6 or more, select | general recommendation, source unverified | Even with 6, radio if all must be compared at a glance and there is room | FM-02, FM-03, FM-06 |
| DF-33 | Behavior after pressing a question chip | Pressing it sends that text immediately as the user's message | general recommendation, source unverified | If the text has a blank for the user to fill in, fill it into the input field and do not send | AI-03 |
| DF-34 | Conversation that follows after regenerating a response | The following conversation is linked only to the version the user was viewing. Switching to another version shows the conversation linked to that version | general recommendation, source unverified | None | AI-04 |
| DF-35 | Asking for a reason after dislike | Choosing a reason is optional, skippable, and not forced | general recommendation, source unverified | An internal tool where the reason is essential for quality improvement | AI-06 |
| DF-36 | Conversation that followed after editing a message | Do not replace it, preserve it as the previous version. Notify that it is preserved before sending | general recommendation, source unverified | A product with storage limits | AI-07 |
| DF-37 | Reflecting selected state in the URL (tabs, filters, sort) | Reflect it (kept after refresh and sharing) | general recommendation, source unverified | A filter value containing personal information, or a simple in-screen toggle | NV-02, IC-06, IC-08 |
| DF-38 | Breadcrumbs on narrow screens | Collapse to the single level directly above, and expand the full path on press | general recommendation, source unverified | The horizontal scroll approach when the path is short and focus movement is not a problem | NV-04 |
| DF-39 | Breadcrumb structured data | Use only on public pages that need search exposure. Do not use on post-login screens | general recommendation, source unverified | None | NV-04 |
| DF-40 | Hiding the header | Always fixed. Only on mobile content screens with scarce vertical space, shrink or hide on scroll down and show again on scroll up | general recommendation, source unverified | Do not hide it on input form screens | NV-05 |
| DF-41 | Page number truncation | Show only the first, last, current page and 1 page on each side, and mark the omitted range with `…` | general recommendation, source unverified | Show all if the total page count is 7 or fewer | NV-07 |
| DF-42 | Off-screen items in infinite scroll | Keep them as they are at first, and virtualize when a performance measurement shows a problem | general recommendation, source unverified | A list with many images or videos is virtualized from the start | NV-08 |
| DF-43 | Identifier on error screens | If the server response gives an error identifier, show it in one line and make it copyable. Do not show an identifier for connection loss | general recommendation, source unverified | Do not show an identifier that contains personal information | ES-08 |
| DF-44 | AI response delay guidance display | Only show a status until the first response event arrives, and do not invent percent, step names, or remaining time | general recommendation, source unverified. | DF-45 | Scope for saving banner dismissal | Save for the session, and save permanently if `다시 보지 않기` (do not show again) is chosen | general recommendation, source unverified | Banners with information that must not be dismissed (deadlines, outages) have no close control at all | FB-03 |
| DF-46 | Badge count refresh timing | Refresh on screen entry and on tab return, and on arrival if push events exist | general recommendation, source unverified | For a server where the refresh call is costly, only on tab return | FB-09 |
| DF-47 | Focus after resetting filters | Move to the first control of the filter area (because the reset button disappears). Announce the change in result count with `role="status"` | general recommendation, source unverified. Focus order: WCAG 2.4.3 | None | ES-03 |
